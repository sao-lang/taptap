# 13 · UI · 技术 · 管线

> 《定线人》设定集 第十三册
> 从 UI、程序、制作人三个角度看这个项目怎么做出来。**含十四神徽色值与 UI 红线（不出现神像、神谕、神选）。**

---

## 一、UI 总原则

### 1.1 竖屏，单手

决定：**竖屏 9:16，主要交互在屏幕下方 40% 区域。**

理由：横屏像素 RPG 在手机上，拇指会挡住半个屏幕。竖屏牺牲视野，换来"能在地铁上单手玩"。

**这是一条会得罪人的决定，但它是产品决定，不是审美决定。**

### 1.2 三条铁律

1. **一屏一功能**。不并排多面板。
2. **拇指可达**。所有常用按钮在屏幕下 1/3。
3. **可关闭的永远可关闭**。战斗中的弹窗必须能一键关掉。

### 1.3 触摸尺寸

- 主按钮 ≥ 56×56 dp
- 次要按钮 ≥ 44×44 dp
- 间距 ≥ 8 dp

## 二、屏幕布局

### 2.1 战斗（旧矿坑内）

```
┌─────────────────────┐
│ 水位  ▓▓▓▓░░░░  ↑  │ ← 顶部：时间条（常驻，最重要）
│ 血量  ██████░░  78  │
├─────────────────────┤
│                     │
│                     │
│      游戏画面        │ ← 中间：视野区（约 55%）
│      （横 12 格）    │
│                     │
│                     │
├─────────────────────┤
│  ◇咒术  ◇道具  ◇跑  │ ← 中部：快捷栏（图标 + 冷却环）
├─────────────────────┤
│   ┌───┐             │
│   │摇杆│    ⚔   ⤴   │ ← 底部：拇指区
│   └───┘             │
└─────────────────────┘
```

**关键点**：
- 时间条在**最顶部**，因为它是最重要的信息
- 摇杆在左，攻击在右，两指可同时操作
- 快捷栏 3 个格子，不多不少

### 2.2 城镇 / 营地

- 上方 60%：场景
- 下方 40%：可滑动的手风琴式菜单（任务 / 商店 / 打造 / 声望）
- **没有"主菜单"**。所有功能都在场景里，点 NPC 或物件进入

### 2.3 地图

分三层：
1. **小地图**（角落，圆形，只显示当前层）
2. **层地图**（点开，显示本层已探索部分）
3. **世界地图**（只在营地可开，显示大陆与国界）

**地图不给"全图"**。没走过的地方是黑的。这是 Roguelike 的基本尊重。

## 三、四个关键 UI 元素

### 3.1 行程表（最重要的一个）

```
      今日 · 头霜月 12 日
  ┌──────────────────────┐
  │ 05:40  排水  -2.1m   │
  │ 11:50  渗涨  +2.8m   │
  │ 18:10  排水  -2.4m   │
  │ 00:20  渗涨  +2.6m   │
  └──────────────────────┘
     明日 · 头霜月 13 日 【汛期】
        旧矿坑开放 06:30–09:10
```

**它必须能被"读熟"。** 老玩家会不看表就知道"明天早上能下城"。

设计上：
- 行程表可以在任何地方打开（一个滑动手势）
- 高亮"下一次渗涨"和"还剩多久"
- 汛期日红色标记

### 3.2 时间条（旧矿坑内）

一根竖直的条，从下往上。

| 区域 | 颜色 | 含义 |
|---|---|---|
| 底部 60% | 绿 | 安全 |
| 60–80% | 黄 | 部分通道淹了 |
| 80–95% | 红 | 只有最近的路能走 |
| 95%+ | 黑闪 | 开始掉血 |

**旁边有一个数字：剩余时间（分:秒）。**

这个数字会让玩家做很多决定。

### 3.3 石纹条

**平时隐藏，只在咒术界面显示。**

理由：石纹是"长期后果"，不是"即时状态"。一直显示会让玩家焦虑，藏起来会让玩家忘记。

**折中方案**：每次咒术使用后，屏幕边缘闪一下白，不显示数字。

玩家会"感觉"到自己用了多少，但算不清。**这是刻意的。**

### 3.4 声望

不显示数字，显示**称呼**：

陌生 → 脸熟 → 认识 → 熟人 → 自己人 → 他们的人

**用词比用数字更有代入感。**

## 神徽与 UI 红线

| 神徽（柱） | 色值 |
|---|---|
| 金 | `#C8A45C` |
| 木 | `#5E8C61` |
| 水 | `#4E8FA8` |
| 火 | `#C4552F` |
| 土 | `#9A8768` |
| 风 | `#8FB8C4` |
| 光 | `#E8D9A0` |
| 电 | `#7C86D6` |
| 音 | `#B077A8` |
| 暗 | `#4A4658` |
| 时间 | `#8C8272` |
| 空间 | `#6F9C9B` |
| 物质 | `#A8A29A` |
| 能量 | `#79B6A6` |

**用途只有四处**：神徽、词条前缀染色、柱日提示、神殿门楣。**不做角色配色**——角色仍按地区与职业穿衣服（00A 第十节）。竖屏小尺寸下神徽用「**色点 + 一字**」，不用图形，避免误认（见 1.1 竖屏、1.3 触摸尺寸）。

**UI 红线（违反即作废，见 00A 第二节缄默律）**

1. 不出现**神像、神谕、神选、天命、祈祷按钮、神迹演出、神明立绘**。
2. 柱日提示只写「××日 · 停业」，不写「神赐」。
3. 遗器详情写「承神：××」，不写「神力」。
4. 所有超自然提示一律用**世俗措辞**（行会、商会、村里的说法），不写神迹。

**玩家端结果**：全程不会把任何一条提示读成神迹，柱日只等于"店关门、账停下"的假日，遗器只比普通装备多一行出处。

## 四、交互规范

| 操作 | 手势 |
|---|---|
| 移动 | 左下虚拟摇杆（可切换为"点击移动"） |
| 攻击 | 右下大按钮 |
| 闪避 | 右下小按钮（双击方向也可） |
| 咒术 | 中下三个快捷格 |
| 交互/拾取 | 靠近自动提示，点击确认 |
| 打开行程表 | 屏幕顶部下拉 |
| 打开背包 | 双击屏幕中央 |
| 暂停 | 右上角 |

**不做多指手势。** 手机上多指手势的识别率太低，会让人烦。

## 五、技术架构

### 5.1 引擎

**Godot 4。**

理由：
- 2D 原生，TileMap 与 AnimatedSprite2D 顺手
- 免费，无授权费
- 导出安卓一步到位，包体小
- GDScript 对独立团队够用，数据驱动方便

**不选 Unity 的理由**：这个项目没有 3D 需求，不需要 Spine 生态，也没有大量素材包要买。

### 5.2 数据结构（最关键的三张表）

#### 装备表

```json
{
  "id": "blade_curve_01",
  "type": "weapon",
  "class": "short_blade",
  "branch": "curve",
  "slot": "main_hand",
  "base_damage": 16,
  "attack_interval": 0.55,
  "hitbox": "arc_90",
  "tags": ["edged"],
  "affix_slots": ["prefix", "suffix"]
}
```

#### 词条表

```json
{
  "id": "wet",
  "type": "prefix",
  "tiers": [15, 30, 45],
  "effect": "apply_status:wet",
  "exclusive": ["salt"],
  "weight": 14
}
```

#### 种族表

```json
{
  "id": "serani",
  "stats": {"str":"C","con":"C","agi":"C","int":"B","per":"B","tide":"C"},
  "slots": ["head","face","torso","arms","legs","feet","back","main_hand","off_hand","acc","acc","acc"],
  "passive": "contract",
  "active": "persuade",
  "origin": "whitecliff_lower"
}
```

**铁律：槽位必须是数组，不是固定字段。**

后续要加"变异槽""外框槽"，只是往数组里 push 一项。

### 5.3 随机地牢生成

不是"纯随机"，是**模板 + 扰动**：

```
1. 选一个"旧矿坑模板"（该城的历史布局，手写 4 套）
2. 按层数切分（每层 1 个模板片段）
3. 扰动：
   - 30% 的房间被淤泥填死
   - 20% 的通道坍塌
   - 随机加 1–2 条"新冲开的路"
4. 校验：从入口到出口必须有通路
5. 放置：怪物点、物资点、事件点
```

**为什么用模板而不是纯随机**：纯随机生成的房间没有"这是城市"的感觉。模板保留了"这是某个人的家、这是条街"的记忆。

### 5.4 存档

- 单存档，自动保存
- 保存点：进入/离开旧矿坑、切换区域、完成事件
- **旧矿坑内不保存**——死了就是死了

这是 Roguelike 的基本契约。

### 5.5 纹满者

玩家石纹 100% 时，把角色数据序列化成一条"纹满者记录"，上传到服务器（可选，需联网）。

其他玩家在同一位置能看到它，读到那句留言。

**离线也能玩，只是看不到别人的纹满者。**

## 六、美术管线

### 6.1 规格

| 项目 | 规格 |
|---|---|
| 角色 | 32×48，4 方向 |
| 地砖 | 16×16 |
| 大型怪物 | 64×64 至 128×128 |
| 素材风格 | 像素，2–3 阶明度，低饱和 |

### 6.2 动画预算（现实约束）

**20 类武器，只做 9 套攻击动画。** 武器靠"命中特效 + 音效 + 数值手感"区分，不靠逐把动画。

| 动画 | 帧数 | 方向 | 覆盖武器 |
|---|---|---|---|
| 横斩 | 4 | 4 | 刀、剑、晶刃 |
| 刺击 | 3 | 4 | 匕首、爪 |
| 劈砍 | 4 | 4 | 斧、战戟 |
| 砸击 | 5 | 4 | 锤、链锤 |
| 大劈 | 5 | 4 | 巨剑、巨斧 |
| 突刺 | 3 | 4 | 长枪 |
| 射击 | 3 | 4 | 弓、弩、铳、投掷 |
| 施咒 | 4 | 4 | 法杖、魔法书、触媒 |
| 抽击 | 3 | 4 | 鞭 |

**共 9 套 × 平均 3.8 帧 × 4 方向 ≈ 138 帧。**

如果 20 类各做一套，就是 20 × 4 × 4 = 320 帧，多一倍多，但玩家感知提升很小。

**差异靠"命中特效 + 音效 + 数值手感"来体现。**

### 6.3 逐把武器的差异怎么体现（低成本方案）

| 手段 | 成本 | 玩家感知 |
|---|---|---|
| 命中特效（刀光/骨屑/火花） | 低 | 高 |
| 音效（金属、钝器、切割） | 低 | 高 |
| 攻击间隔与后摇 | 无 | 高 |
| 屏幕反馈强度（抖动/顿帧） | 无 | 高 |
| 逐把动画 | 极高 | 低 |

**所以优先做前四项。**

### 6.3 命中反馈四件套

1. **顿帧**：命中瞬间双方定格 60–80ms
2. **抖动**：重击 2px / 暴击 4px
3. **击退**：轻击 8px / 重击 24px
4. **伤害数字**：带随机偏移，暴击更大更亮

**这四样做不好，美术再好也白搭。M0 就要验证。**

## 七、音频

| 类别 | 数量 | 说明 |
|---|---|---|
| 环境音 | 8 | 渗水声、风、雨、矿尘簌簌 |
| 战斗音 | 24 | 6 类武器 × 命中/挥空 |
| UI 音 | 12 | 点击、翻页、确认、警告 |
| 音乐 | 6 | 营地、城镇、旧矿坑、Boss、结局、标题 |

**最重要的一个音效：矿坑渗水警报——一段由远及近的水声加上铜钟。**

它在城里敲三下，玩家就知道"该走了"。**这是听觉版的 UI。**

柱日钟声用「不响的初声之钟」意象做低频留白，不做神圣合唱、不出现人声神谕。

## 八、里程碑

| 阶段 | 周期 | 交付 | 验证什么 |
|---|---|---|---|
| **M0** | 3 周 | 一个角色、一把刀、一只滩蟹、一个房间 | 打起来爽不爽 |
| **M1** | 4 周 | 旧矿坑一层、时间条、行程表、撤离结算 | "贪"的感觉对不对 |
| **M2** | 4 周 | 装备与词条、属性成长、石纹 | 配装有没有意义 |
| **M3** | 6 周 | 三座旧矿坑、主线前四章、3 个种族 | 能不能上架试玩 |
| **M4** | 8 周 | 全主线、声望、经济、宠物、载具 | 完整版 |

**M0 如果手感不对，后面全部推倒。** 这一条要写进合同。

## 九、风险清单

| 风险 | 概率 | 应对 |
|---|---|---|
| 竖屏导致战斗空间太小 | 高 | M0 就要验证；不行就转横屏（但要重做 UI） |
| 时节系统让玩家焦虑 | 中 | 提供"暂停渗水"的辅助选项（消耗道具） |
| 故事太压抑，玩家不愿看 | 中 | 加入"轻松支线"（宠物、农场、酒馆闲聊） |
| 石纹惩罚太重，玩家不敢用咒术 | 高 | 前两阶的成本降低一半；只有三阶重 |
| 内容量不够，20 小时就通关 | 中 | 旧矿坑程序生成 + 势力任务链补内容 |
| 独立团队做不完 | 高 | M3 就是"可上架"的最小完整产品，做不完就发 M3 |

## 十、给制作人的一句话

**这个项目的最大风险不是技术，是"想做的太多"。**

M0 做不完，就不要开始写剧情。

**手感是一切的地基。** 地基不牢，故事再好也没人玩到第二章。
